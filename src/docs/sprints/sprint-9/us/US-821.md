## Historia de Usuario

> Como jugador, quiero abrir un panel de filtros que se desliza sobre la lista de ciudades (sin tapar el mapa), con solo las secciones relevantes a las capas que tengo activas, para refinar mi búsqueda sin perder el contexto visual del mapa.

---

## Diseño

Ver README del mockup para el detalle completo de estilos, colores y tokens. Resumen funcional:

- **Vista lista (default):** layout vertical en dos filas: fila 1 = search input (ancho completo); fila 2 = botón "Filtros" (ancho completo, centrado) + botón limpiar rápido (✕, solo visible si hay filtros activos, al lado derecho del botón Filtros). Luego header "CIUDADES" con contador + lista de ciudades.
- **Vista panel (al click en "Filtros"):** desliza sobre **toda el area del sidebar** (`height: 100%`, `transform: translateX`, `0.32s cubic-bezier(0.16,1,0.3,1)`), lista se desplaza a `-100%`. El panel cubre la lista pero NO el search — el search queda visible sobre el track deslizante (sticky arriba del sidebar). El mapa nunca se cubre — vive fuera del sidebar.
  - Header del panel: "‹ Volver" — "FILTROS" — "Limpiar"
  - Grupo **Clima** (si `activeLayers.clima`): group header azul (`#58a6ff`) + acordeones: Condición (pills grid 4 cols, multi-select), Región (pills wrap, single-select), Tipo Clima (grid de tipos Pokémon — ver nota de dominio abajo, multi-select), Ordenar (radio list, single-select).
  - Grupo **Nidos** (si `activeLayers.nidos`): group header verde (`#22c55e`) + acordeones: Tipo Pokémon (pills grid 3 cols, multi-select), Ordenar (radio list, single-select).
  - Si ninguna capa activa: mensaje "Activa Clima o Nidos en el header para ver filtros".
  - Footer: botones "✓ Aplicar" (flex:2) / "✕ Cancelar" (flex:1) + link "✕ Limpiar todos los filtros".
- **Pills resumen sobre el mapa:** cuando hay filtros activos, aparecen pills flotantes arriba-izquierda del mapa (azul para Clima, verde para Nidos).

### Nota de dominio: "Tipo Clima" en el mockup

El mockup rotuló una sección "Tipo Clima" sin conocer el dominio de la app. En el código real, esa sección corresponde al filtro **`typeFilter`** ya existente — tipos Pokémon potenciados por la condición climática actual — no a una clasificación de clima (tropical/seco/templado/polar). Se implementa con el mismo componente visual de grid que "Tipo Pokémon" en Nidos (círculo de color + emoji + nombre de tipo), reutilizando `POKEMON_TYPES` / `TYPE_IMAGES`.

## Criterios de Aceptación

- [ ] Botón "Filtros" + search + botón limpiar rápido reemplazan el `FilterPanel` inline actual arriba de la lista de ciudades
- [ ] Click en "Filtros" desliza el panel sobre la lista; mapa permanece 100% visible en todo momento
- [ ] Click en "‹ Volver" o "✕ Cancelar": el panel se cierra y **descarta** cualquier cambio hecho en esta apertura (rollback al estado antes de abrir)
- [ ] Click en "✓ Aplicar": el panel se cierra y los cambios quedan persistidos (el feed se re-filtra con los nuevos valores)
- [ ] Click en "✕ Limpiar" (header o footer): resetea el borrador de filtros a sus defaults, sin cerrar el panel
- [ ] Botón limpiar rápido (junto a "Filtros", vista lista): mismo efecto que Limpiar pero sobre el estado real (aplicado), sin abrir el panel
- [ ] Si solo Clima está activo: solo aparece el grupo Clima (Condición, Región, Tipo Clima, Ordenar)
- [ ] Si solo Nidos está activo: solo aparece el grupo Nidos (Tipo Pokémon, Ordenar)
- [ ] Si ambos activos: ambos grupos visibles, cada uno con su group header de color
- [ ] Si ninguna capa activa: panel muestra mensaje de estado vacío
- [ ] Cada acordeón se expande/colapsa independientemente al click en su header; abre con badge de conteo si tiene selección activa
- [ ] Badge de conteo total en el botón "Filtros" = suma de filtros activos de todas las capas visibles
- [ ] El estado de los filtros de cada capa se preserva al desactivar y reactivar esa capa (ya cubierto por el store existente)
- [ ] Pills resumen aparecen sobre el mapa cuando hay al menos un filtro aplicado (no borrador)
- [ ] Los subcomponentes visuales (accordion section, pills grid, pills wrap, radio list, group header) son compartidos con `FilterPanelModal.tsx` (mobile) — no hay duplicación de JSX/CSS entre ambos

## Estado (Zustand) — nuevo slice

```ts
// UI
filterPanelOpen: boolean
accordionState: {
  condicion: boolean    // default true (abierto)
  region: boolean
  tipoClima: boolean
  orden: boolean
  tipoPoke: boolean     // default true (abierto)
  ordenNidos: boolean
}

// Borrador — clonado del estado real al abrir, descartable al Cancelar
draftFilters: {
  region: Region
  condition: string[]
  type: string[]          // "Tipo Clima" en el panel — reutiliza typeFilter
  sortMode: SortMode
  nestType: string[]
  nestSortBy: 'name' | 'type' | 'spawnRate'
}

// Acciones
openFilterPanel(): void        // clona regionFilter/conditionFilter/typeFilter/sortMode/nestTypeFilter/nestSortBy -> draftFilters; abre panel
setDraftRegion(region): void
setDraftCondition(conditions): void
setDraftType(types): void
setDraftSortMode(mode): void
setDraftNestType(types): void
setDraftNestSortBy(mode): void
toggleAccordion(section): void
applyFilterPanel(): void       // draftFilters -> campos reales; cierra panel
cancelFilterPanel(): void      // descarta draftFilters; cierra panel
clearDraftFilters(): void      // resetea draftFilters a defaults; NO cierra panel
clearAppliedFilters(): void    // botón limpiar rápido — resetea filtros reales directamente
```

## Validación

- [ ] Con solo Clima activo: solo aparece el grupo Clima en el panel
- [ ] Con solo Nidos activo: solo aparece el grupo Nidos
- [ ] Con ambos activos: ambos grupos, con sus colores correspondientes
- [ ] Con ninguno activo: mensaje de estado vacío
- [ ] Aplicar un filtro de Condición reduce el feed correctamente
- [ ] Abrir panel, cambiar varios filtros, click Cancelar: el feed NO cambia (filtros reales intactos)
- [ ] Abrir panel, cambiar filtros, click Aplicar: el feed SÍ cambia con los nuevos valores
- [ ] Limpiar dentro del panel resetea el borrador visualmente sin cerrar el panel ni tocar el estado aplicado hasta que se de Aplicar
- [ ] Botón limpiar rápido en vista lista limpia filtros aplicados sin abrir el panel
- [ ] Cambiar de capa activa no resetea los filtros de la otra capa
- [ ] Transición de slide es fluida (sin salto de layout, mapa no se re-renderiza de más)
- [ ] No hay regresión en `FilterPanelModal.tsx` (mobile) tras extraer los subcomponentes compartidos

## Notas

- Prioridad de espacio: acordeones abiertos por defecto son Condición (Clima) y Tipo Pokémon (Nidos) — igual que en el mockup — el resto arranca colapsado.
- El panel se monta siempre (no condicional al `isOpen`) para permitir la animación de `transform`; se oculta con `pointer-events: none` y el desplazamiento fuera de vista, igual que la lista.
- Los tags de color por capa (`#58a6ff` Clima, `#22c55e` Nidos) son valores hardcodeados del mockup — igual que ya ocurre en `FilterPanel.tsx` inline actual. Evaluar si migrar a tokens del design system en limpieza futura (no bloquea esta US).

## Subtarea: Homologacion de datos y visuales al original (sesion 4)

El nuevo panel deslizante implementa la estructura correcta pero perdio los datos y visuales del componente original (`FilterPanelModal.tsx`). Esta subtarea los restaura sin tocar el diseño nuevo.

### Diferencias a corregir por componente

#### `FilterPanel.tsx` — datos de condicion climatica
- Labels en ingles (`Sunny, Partly...`) → restaurar a español: `Soleado, Parcial, Nublado, Niebla, Lluvia, Nieve, Ventoso`
- Emojis Unicode → restaurar imagenes `<img src="/weather/*.png">` (24x24, `object-fit: contain`)
- Agregar pill extra "Todos" (`value: ''` = limpiar seleccion) al inicio del grid

#### `FilterPanel.tsx` — datos de region
- Labels sin acentos → restaurar: `Todas, Asia, Europa, América, Oceanía, África`
- Quitar emojis del label (el mockup original los ponia via CSS `::before`, no en el texto)

#### `FilterPanel.tsx` — Tipo Clima y Tipo Pokemon
- Imagenes `/types/ico_N_nombre.webp` (28x28) → usarlas en las pills en lugar de solo el nombre
- Agregar pill "Todos" al inicio (`value: ''` = limpiar seleccion)
- Grid 3 cols → cambiar a 3 cols para tipo (ya esta bien) pero mostrar max 9 primero con boton "Ver mas tipos"

#### `filters/AccordionSection.tsx` — icono de seccion
- Agregar prop `icon?: string` (emoji) que se muestra a la izquierda del label en el header
- Iconos por seccion: Condicion `⛅`, Region `🌐`, Tipo Clima `🌡️`, Ordenar Clima `↕️`, Tipo Pokemon `⚡`, Ordenar Nidos `↕️`

#### `filters/AccordionSection.tsx` — badge descriptivo
- Badge actual muestra solo numero → cambiar a texto descriptivo igual que el original:
  - Sin seleccion: `"TODOS"`
  - 1 seleccionado: el label de ese item en mayusculas
  - 2+: `"N SELEC."`
  - Para sort: el label de la opcion activa o `"SIN ORDEN"`

#### `filters/RadioList.tsx` — soporte asc/desc
- Agregar prop `sortDirection?: 'asc' | 'desc'` y `onToggleDirection?: () => void`
- Si la opcion activa se re-clickea → toggle de direccion, muestra `↑` o `↓` al lado del label

#### `filters/RadioList.tsx` — opciones de ordenar Clima
- Restaurar labels con emojis: `🔤 Sin orden · 🔤 Nombre · 📊 Densidad · ⭐ Rating · 🕐 Hora Local`

#### `filters/GroupHeader.tsx` — subtitulo
- Agregar prop `subtitle?: string`
- Clima: subtitulo `"Condición · Región · Tipo · Orden"`
- Nidos: subtitulo `"Tipo Pokémon · Orden"`
