# US-901 — Code Splitting Firebase SDK

**Sprint:** 9  
**Priority:** P0 (bloqueante)  
**Story Points:** 5  
**Status:** 🎯 PLANEADO  
**Sesiones:** 3

---

## Problema

Firebase SDK no está tree-shaken, añade 890 KB (gzip: 430 KB) al bundle.

---

## Solución

Implementar dynamic imports para módulos Firebase que se cargan solo cuando se necesitan.

---

## Subtareas

### Subtarea 1: Dynamic Imports Setup (1.5 SP)
**Objetivo:** Configurar Vite para dynamic imports

```typescript
// Antes:
import { getFirestore } from 'firebase/firestore';

// Después:
const firestore = await import('firebase/firestore')
  .then(m => m.getFirestore(app));
```

**Archivos:**
- Vite config updates
- firebaseConfig.ts refactor
- serviceWorker setup (si necesario)

## Decisiones Técnicas

### Code-Splitting Strategy
**Opción A:** Vite micro-frontends (overcomplicated)  
**Opción B:** Rollup dynamic imports (ELEGIDA)

Usar dynamic imports simples + Vite defaults.

### Async Loading Pattern
```typescript
// Patrón para usar en componentes
const loadFirestore = async () => {
  const { getFirestore } = await import('firebase/firestore');
  return getFirestore(app);
};
```
